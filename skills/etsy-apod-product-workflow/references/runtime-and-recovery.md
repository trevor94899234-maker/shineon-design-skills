# Local, remote and agent execution

The workflow is portable; tool access and successful execution are runtime-specific. “SE” is treated as the user's remote/agent environment label until an actual destination is identified, not assumed to mean a particular service. Do not claim remote deployment or live compatibility from a local ZIP.

## Capability preflight

Record actual available capabilities, authorized route and one observed result where use is needed:

| Capability | Check | If absent |
|---|---|---|
| Required Skills | Resolve coordinator + Growth + Integrated Coach + Studio by name; inspect applicable refs | Provide exact missing dependency; continue phases that have complete instructions, do not pretend it was invoked |
| Source assets | Original art, same-product mockup, logo and existing records are actually readable; verify transferred hashes | Recover through authorized attachment/download/transfer; ask only for irretrievable essentials |
| Files/artifacts | Writable authorized output, stable paths, image inspection, hashing and user-readable delivery | Use supported artifact storage/export; never report an inaccessible path as delivered |
| Research | Authorized Vault/source access and needed connected tools, source-order decision and limits | Reuse saved evidence; preserve TBC; do not silently invent metrics or buy access |
| Generation | Current Studio default is ChatGPT web image creation through IAB; verify actual page/control and native download | Preserve prepared prompts; explicit route change before another service/API; no browser route substitution through this Skill |
| APOD | Correct product accessible in supported authorized browser/tool, normal upload/save/reopen | Local work can continue; actual APOD completion remains pending |
| Owner interaction | Supported question, image preview and login/challenge handoff mechanism | Save a reviewable pending packet; no silent acceptance |
| Verification | Actual file dimensions, hash, UI readback, remote asset retrieval when supported | Report the weaker available proof; no fabricated byte identity |

Prefer a sufficient connected service tool over browser use, subject to the owner's explicit route preferences. Discover current tools and read their documentation. Never assume a historical tool name, tab ID, DOM selector, endpoint, shell or path exists in this runtime. Use the relevant computer/browser Skill when actually controlling a browser, and follow its first-call and security-stop rules.

Local shell examples must use the discovered runtime executable; do not assume `python` resolves correctly on Windows. The optional audit helper is Python standard library only. If Python is absent, perform the documented checks with supported tools and report that the helper was not run; installing a runtime is not implied.

## Handoff contract

Keep one coordinator, current-state writer and browser operator. Reading a supporting Skill does not authorize new agents. Delegation requires the current user/rules to permit it. If delegated, assign disjoint artifacts; workers return receipts and never mutate shared current state or take over the browser. Claim/release the operator in the record; recheck the destination after any handoff.

Transfer only the task's authorized files and minimum records. Use relative task paths inside a package. Include source and candidate hashes, product IDs, exact owner decisions, scope/exclusions, active roles, pending jobs, per-role attempt history, selected candidate versions, uploaded asset map, current fields and the next safe action. Do not include cookies, tokens, credentials, encrypted assistant links, unrelated documents or account dumps.

The receiver verifies the package manifest and readable assets, confirms current product state, adopts the existing run ID and decisions, and resumes the first unmet dependency. It does not reset attempts, re-ask accepted questions, re-upload all files or restart research. Local `C:/...` paths are historical pointers until a supported transfer makes the bytes available remotely.

## Recover the failed layer

| Observation | Next safe action |
|---|---|
| Generation still pending | Inspect the same job/conversation via documented UI; preserve submission ID and attempt |
| Observation/download timeout | Check whether output/file already exists; retry retrieval within supported limits, not generation |
| Terminal generation failure | Record terminal evidence; change only the justified prompt/reference issue within remaining attempts |
| Multi-role output duplicates/omits roles | Count actual files and distinct roles separately; use one-role compact prompts within budget |
| Browser/API general connection error | Determine current runtime/tab/action state using allowed diagnostics; do not infer logout |
| Old tab no longer in current inventory | If normal recovery is allowed and no safety stop applies, open the known URL in the same authorized browser; do not reuse historical tab IDs |
| Upload/save timeout | Inspect selected count, asset identity, button/job state and stored values before any retry |
| Supplier renderer failed but artwork saved | Preserve native-save proof; diagnose renderer stage, do not erase art or call it a browser failure |
| Login/challenge page | Owner handoff; pause dependent browser actions, continue independent local work |
| Explicit safety/policy stop or denied action | Stop that path; only documented permitted recovery/owner decision, never a controller reset or environment switch to evade it |

Use fresh observed DOM state after rerenders. A tool error may follow a successful action; state wins over the error message. Retry only when evidence supports that it is safe. Keep a short operation journal: intended action, exact target, attempted/unknown/applied, observed state and recovery. Do not log secrets.

## Package and installation

The five-folder bundle contains this coordinator and the four existing entrypoints (Growth, Coach, Studio, ornament adapter) at the manifest's versions. It is a transport snapshot, not proof the destination loads Skills. Other specialized Skills, browser controls, account connections and product files are conditional runtime dependencies, not included services.

On a new environment, use its documented Skill installer/storage and explicit target mapping. Review existing versions before overwrite; preserve local edits and back up any authorized replacement. Verify exact installed bytes and metadata, then run a no-live-action smoke scenario. Installation on an unnamed remote destination is not authorized or completed merely because the user requested portability. Never modify security policy or create a recurring sync to make the bundle work.
