# Agent handoff and dependency intake

Use for an upstream agent handoff, owner clarification, or partial/pilot request. These rules change intake decisions, not fidelity, permission or final acceptance requirements.

## Recover answers before asking

Read the current brief, referenced readable files, the local task checkpoint and owner replies. Reconcile by exact SKU/design revision. Explicit current owner decisions control within their scope; retain original source wording and provenance rather than promoting an agent's suggestion to owner approval. If ownership/identity or actual conflicting evidence cannot be resolved, pause only dependent work.

Keep a compact confirmed/unknown/changed summary in the existing task artifact. It need not be a new database or mandatory form. A fact's status and the asset needed to depict it are separate: an owner-confirmed page count can support copy while an unseen interior remains unavailable to draw.

Before any question: reuse prior current-scope decisions → inspect readable sources → exercise delegated routine judgment → omit optional unsupported claims → ask only the remaining material owner decision. Target zero routine questions. Batch row-level method/budget/fidelity exceptions after independent work instead of asking image by image; do not relax required gates or the requested count.

An upstream copy/role lock may be `OWNER_APPROVED`, `OWNER_DRAFT_AUTHORIZED`, or `AGENT_IMPLEMENTATION` with a pointer to delegated wording/composition authority. The latter is usable in that scope and must never be relabeled owner-approved. Studio preserves the exact locked copy; an agent cannot use delegation to waive a real human gate. Record `human_gate=NOT_REQUIRED` with basis for routine in-scope work, or the actual required/pending/satisfied gate. Do not add a new owner approval merely because the upstream author was an agent.

For each fact record only what matters: value, SKU, source/date or owner reply, and any affected rows. Reuse the confirmation. Do not demand a supplier screenshot, fresh policy answer or word-for-word approval already given unless the brief explicitly needs it or new conflicting evidence matters.

A statement that a ZIP/file exists is not file access. Check the supplied location/attachments and a bounded likely local location; request one usable path or attachment if inaccessible. Report “not read/inaccessible,” not “absent from the package.” Do not keep searching unrelated folders or ask the owner to retype all data inside an unread ZIP.

## Select the smallest sufficient brief

| Phase | Required now | Does not block by itself |
| --- | --- | --- |
| Source/brief review | Readable requested source material and the review question | Generation settings, full set completion or publish permission |
| One-row fidelity pilot | Exact product/design ID; readable reference showing the requested view; exact printed text and supplied overlay or explicit none; required logo; supported scene; one-pass/workflow lock; size target; authorized selected row and attempt history | Full description/tags/keyword metrics, unseen interior/back photos or unfinished other rows when this pilot uses none of them |
| Selected production rows | Pilot inputs plus upstream locked copy/roles under recorded authority and facts/positioning used by those rows | Evidence for unrelated roles; policy questions for claims omitted from these rows |
| Complete set | Approved N-row coverage, selected files and all applicable per-row/format/fidelity/review checks | Nothing may be counted complete merely because a prompt or a partial set exists |

An absent listing title blocks a positioning decision only when the selected image depends on it. Reuse existing approved context; do not invent a new sender, recipient, occasion, SEO claim or substitute title. If no new positioning is needed, keep the established neutral/supported scene and proceed within scope. Do not label a fidelity pilot as SEO-approved.

Total requested set count, currently active generation count, supplied draft-copy count and final accepted count are distinct. A submitted 20-row brief is not permission to run 20 jobs; a pilot pause/retry limit remains active. Owner authorization to generate local drafts permits using the specified draft text as drafts; final copy/image acceptance is separate. Do not turn a local draft task into a fresh owner-approval loop.

## Route gaps by their actual effect

For each unresolved item state the affected row, why the item is needed, the minimum remedy and whether other work can proceed. Use these distinctions:

- **Data/access:** a reference or required fact is unreadable or missing. Locate/reuse it first, then request only the needed source. Better reference detail can help fidelity but does not prove a generator's native output size.
- **Owner decision:** a material new wording outside delegated copy authority, source replacement, scope/cost/workflow change or unresolved critical conflict needs a decision. Routine exact-copy execution and delegated composition do not. Do not ask again for a decision already authorized in this session.
- **Tool/output:** native size, unsupported controls, failed exact print/logo or anatomy. Diagnose using actual settings and returned files; do not reclassify this as missing listing/SEO data.
- **Unrelated/optional:** preserve as TBC or omit the unsupported claim. Continue authorized independent rows.

Collect only necessary questions in one concise batch after recovery. Give the reason and effect for each; do not repeatedly restate the whole history of confirmations. Later questions need a new material conflict or newly selected dependency, not an old unanswered optional field.

## Rendering feasibility before repeated attempts

Inspect the available tool schema and the existing native files. Keep requested size, actual supported controls and decoded returned dimensions separate. A prompt saying “2048” or “preserve exactly” proves neither. Do not invent size/reference-strength parameters, native capability or paid-route pricing.

On repeated undersized or distorted output, stop repeating the same method. Continue permitted diagnosis and prepare a concrete alternate route/settings/cost proposal only if needed; do not silently execute a paid API, inspect credentials, lower acceptance, paste text/logo or upscale to satisfy a native target. A future test still counts against the existing row's attempt history. Follow a stricter owner retry limit when present.

## What an upstream agent should hand over

Accept an accessible ZIP or one self-contained document plus assets; do not require six parallel documents for a simple pilot. For a larger batch, reuse one authoritative per-SKU plan. The downstream agent may calculate local hashes/dimensions; the owner need not manually type them.

Include:

1. Product/design IDs and brief revision; current owner confirmations and exceptions with provenance; existing accessible source/QA pointers.
2. Requested phase, total N, selected active rows, paused rows, generation/draft authority, budget/retry boundaries and prior attempts. No upstream agent can grant permissions the human has not given.
3. Accessible original product/artwork/logo assets with filenames and authority by purpose: complete named product/layout, static artwork only, shape/context or actual interior. A static PNG without names must not delete names shown in the authoritative named product. Do not use another SKU to fill gaps.
4. Exact visible printed text, punctuation and line groups; motifs, grain, geometry, visible hardware and unknown surfaces; source-supported angle for each active row.
5. Exact overlay with line breaks, role/buyer question, scene/props and copy status. Provide the same-SKU title/description/tags and keyword/positioning context for rows that use them; identify historical versus current and approved versus suggested. Do not make fresh keyword research mandatory for every visual retry.
6. Output aspect/native target, whole-image/compositing constraint, original logo requirement, QA checks and a short row-specific gap list. Owner-confirmed policy copy may be used within its actual scope; do not turn destination-dependent estimates into delivery guarantees.

Return a compact receipt: inputs actually read; reused owner confirmations; active rows ready or their exact dependencies; tool/decision issues; next concrete action. Access status, intake readiness, generated, fidelity-passed, dimension-passed and accepted are separate; do not call a data-ready pilot a passed image.

For returned candidates, reconcile the producer's exact delivered path/hash, source revision and QA receipt with the receiver's actually opened path/hash before judging the report. If they differ, locate and inspect the delivered artifact first; another pilot's features cannot refute its QA. Preserve both historical reports and add a dated, file-bound correction only where supported. Keep the receipt in the existing record; an optional compact line is `product/revision | delivered path + SHA | reviewed path + SHA | source/QA receipt | checker/time | matched, mismatch or unverified`. This adds no new mandatory form or database; filenames, sequence numbers and modification times alone are insufficient.
