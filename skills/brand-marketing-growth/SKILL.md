# 品牌營銷與增長

## 已選產品：完整私人 APOD 流程

Owner 已選實體 POD 產品並要求「定位／research → thumbnails → listing 全部資料 → Anywhere POD 保存」或續做時，接 [etsy-apod-product-workflow](../etsy-apod-product-workflow/SKILL.md) 作唯一跨階段協調入口。本技能只交定位、買家任務、claims 及角色方向；由該入口調用時完成本階段後回傳，不再啟動另一份流程。重用已回答的同輪來源次序及方向；例行執行不用逐圖問，真正外觀例外／業務決定仍按相應 gate。單做 marketing research、定位或圖片，保留其較窄範圍。

## Ornament 掛飾：由 Growth 接到私人 APOD

當 owner 已選 ornament／聖誕掛飾／個人化吊飾，並要求完整 listing、thumbnail 接到 APOD、續做或補漏時，讀 [etsy-ornament-apod-workflow](../etsy-ornament-apod-workflow/SKILL.md)。它整理同一款的策略 → actual mockup → 研究／文案 → 圖片 → 私人 APOD 保存驗證，保留完整 build 的影片要求及最新 local-only／不改運費等範圍決定。尚未選產品的探索仍用本技能既有方法。

只做 ornament thumbnail 時直接接現有 Studio 及其 [ornament 配方](../etsy-listing-image-studio/references/ornament-thumbnail-profile.md)，不擴大成 full build。若已由該 workflow 調用本技能，只交回定位、Bundle 判斷、價格口徑及 learning 草案，不再次啟動入口／另開計劃。新入口不增加平台寫入、影片上載或 Etsy 發佈權限。

## Thumbnail 生產接力（owner 2026-10-27 更新）

本技能負責買家定位、人物關係、場合、用途、個人化與情感故事及已授權文案／角色計劃；實際 thumbnail 生圖及逐檔 QA，預設直接讀取並交由本機 `etsy-listing-image-studio` 執行，沿用它的內置瀏覽器 ChatGPT 網頁版入口與 reference-led 方法。不要等 owner 每次再點名 Studio。`etsy-pod-image-prompts` 只在需要時提供角色／提示詞及來源參考，不是另一個縮圖執行入口，也不必每次先經它。

新產品／新方向先交一份短計劃：實際產品及來源、買家／送禮人／收禮人、場合／用途、N 張不同角色、文字／個人化及實際生圖入口；owner 確認方向後，按 Studio 的起手規則先一張 pilot 及 QA，再續做其餘已授權 rows。重用同輪匹配的確認及已驗 pilot，不逐圖重問，也不承接上一款的故事、規格或例外。此處只串起策略交接，具體生圖及接受方法以 Studio 為單一正式版本。

Owner 提供產品連結時，先在已授權可讀範圍自行讀取頁面，確認實際產品／variant，從正常下載／公開素材入口取得適用同款 mockup、規格及個人化證據，並記錄來源及實際檔案；優先重用已有可讀原稿／logo，不預設要求 owner 逐張重傳。連結是找來源的起點，不保證含有所有資料、素材權利或登入權限；不可用另一款填缺口。私有頁、無法存取素材或本機檔案對雲端不可讀時，先說明實際缺口，只索取最少必要匯出／附件；不提取憑證或繞過存取限制。產品連結本身不授權平台改動或無限生成；完整 listing build 仍沿用整合教練的來源／實際 mockup／研究階段閘門，圖片任務則用 Studio 的最小足夠 brief。

生圖前簡短交代實際讀取的生產 Skill、入口、同款來源及已授權 active rows；有現行讀檔／頁面證據才可說已採用，不把路由文字當成實際執行成功。Studio 不可讀或網頁入口不可用時回報確切阻礙，不自行回退舊內置生圖／API 方法。後續 owner 明確指示可覆蓋預設。這是接力分工，不是建立另一個 agent、換模型或新增生圖、花費、登入、發布權限；保留原來源、數量、重試、QA 及 exact-file owner 決定。

## 先選工作模式

- 定位：誰買、送給誰／如何使用、為何現在需要、真正差異及證據。
- 診斷：資訊是否清楚、能否到達合適受眾、有效外連、產品頁理解、成交及履約，先找最早未解環節。
- 策劃：一個核心題材、少量現有渠道、可負擔素材及行動引導。
- Bundle產品組合：同主題、相近或互補產品如何完成一個送禮任務；連同價格吸引力、每單貢獻及履約可行性判斷。
- 案例研究：核實身份、來源、時點與樣本，再區分值得學的機制和不可移植的條件。
- 實驗檢討：保存基線與單一主要變量，根據真實訊號決定保留、修正、暫停或未定。

一般問題不用全部模式，也不用集合所有教練。通常一個主方法已足夠，第二個必須提供不同決策貢獻。報告、審計及解釋預設繁體中文；客戶看到的美國市場文案可用自然英文。保留人物名、精確原始標題、URL及技術識別碼。

## 先核背景

從目前對話、產品紀錄及已授權來源取得目的、買家／收禮人／送禮人、場合、SKU、已確認規格、素材權利與實物可用性、現有渠道、基線、預算、可用工時及授權。已知不用重問；非必要未知保留待補，會改變決策的關鍵缺口才問。

MyGiftStyle當前提供的背景是基督教家人／朋友禮物、個人化印刷journal、200頁間線、約90至95%美國客人、典型US$49.95、90日零自行投放及每週3至5小時行銷。2026-10-12最新工作紀錄另列整體生意每天最多2小時；這是包含履約／客服的總容量上限，並非新增行銷預算。這些是有日期的使用者背景，日後以最新明確資訊及實際SKU為準；價格不是當前款式核價。零廣告計劃的起止日未知，不能每次重新起算。間線內頁不是guided prayer、預寫經文或練習題。

## 核心流程

開始新的 keyword／產品市場研究，先完成上述來源次序確認。若選 Keyword Vault 優先，先重用可追溯原詞觀察；Vault 已有詞不為補欄位、數據舊或來源衝突而自行重查 EverBee。若 owner 選 Online Search 優先，仍須遵守當次來源／配額授權；選項不自動授權買額度或擴大範圍。多個研究共用去重台帳；配額按provider分開記錄，依當輪owner授權，不能把單一provider餘額套到另一個provider。

1. 確定一個要改變的決定，以及目前最早未解瓶頸。
2. 寫清公開事實、來源、事件／資料日期、查閱日、樣本和未知；不可只看標題或名氣。
3. 抽出可能機制，例如場合選品、真實產品教育或服務信任。明標分析推論，不能由案例直接推定因果。
4. 檢查本店產品、客群、平台、成本、人手及素材是否相容。大品牌的預算、知名度、供應網或服務保證不能憑空移植。
5. 準備一項最小實驗，保持主要變量可辨識；必要時只交可審閱草稿。
6. 記錄主指標、分母、基線、期間、混雜因素、工時及停止／未定條件。無足夠曝光或到訪，不能宣判利基失敗。
7. 用真實後續結果修正下一步。策略討論、草稿、批準、已套用及已量度保持不同狀態。

## 原創系列與產品製作接力

探索下一系列時，先讀[既有系列引用的開放探索A–F段](references/cohesive-series-production-workflow-2026-10-10.md)：固定查證／比較／重用方法，產品與題材保持開放；先跨載體／場合短名單、原創機制及成本工時，再由店主選方向。只對會改變決定的資料重核，不重跑全品牌庫。上游不得提前查詞／選詞、listing文案或thumbnail。先按買家實際收到的交付分流：實物／POD完成指定產品的實際APOD mockup匯出核對後接既有十步；數碼先完成真實檔案清單、內容／授權及可開啟的交付預覽，再接同一Etsy整合教練的SEO方法。詳見[Digital來源與兩分支橋接](references/digital-coach-growth-bridge-2026-10-13.md)。

遇到premium Christian家人／朋友個人化禮物、跨產品系列或Bundle設計，讀[系列設計至生產檔流程](references/cohesive-series-production-workflow-2026-10-10.md)。用同一送禮任務串起「核實參考 → 原創一致系列 → 真實SKU準確預覽 → 店主批准指定設計版本 → 可編姓名母版及已驗證生產檔」。品牌參考不是可複製圖稿，預覽不是實物證明，批准設計不等於批准採購或刊登。premium是待用產品與服務證據支持的定位，不是未核材質、包裝或溢價承諾。

跨SKU同主題可成立為系列，但只有一起購買的理由、完整成本與履約通過才成為Bundle候選。未核第二件SKU時，先做系列方向／缺口，不把概念畫成可售組合。與Etsy整合教練沿用同一產品紀錄、姓名欄、證據狀態及每週3–5小時行銷預算，並服從整體生意每天最多2小時的容量上限。

## Bundle作為固定策略檢查點

使用者於2026年10月9日明確要求：在選品、系列規劃、送禮故事、定價討論及每週增長檢討中，經常主動檢查同主題、相近或互補產品能否組成有吸引力的Bundle，讓增長亦有較高客單價的路徑，避免策略只停留於小額單件訂單。將它保留為長期策略偏好；不是每段回答重複提醒，也不是禁止單件或要求每次推出套裝。

在上述決策點給出「值得驗證／先補資料／暫不適合」及一個理由，再按需讀[Bundle產品組合方法](references/bundle-product-combination.md)。有相容且可履約的候選時，優先提出一個最小測試；產品真實性、成本或履約仍有關鍵缺口時，先處理缺口。不為湊件數加入無關產品、臆造產品名稱或把口述未明詞當成已核實SKU。

先核實每件實際產品、個人化規則、成本、運費與分批寄送，再形成組合價格草案。價格較吸引、AOV較高及利潤增加是不同判斷；缺成本不填售價或折扣，不保證Bundle一定更賺。保留適合的單件選項，按真實轉換、每單貢獻及工時決定是否繼續。
