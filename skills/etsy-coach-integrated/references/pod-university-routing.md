# POD University 方法按需使用

這是既有 Etsy Coach 的資料路由補充。Etsy Coach繼續持有同一份推薦／草稿；本頁只指定何時查已安裝的POD University知識，不建立另一套選品、keyword、APOD或發佈流程。

## 何時自動取用

從使用者需求推定，不要求使用者記Skill名稱：

| 當前問題 | 只讀相關資料 |
|---|---|
| ShineOn／POD選品、收禮對象、場合、用途、journal／acrylic訊息或印刷適配 | [產品／訊息／設計](../../pod-university-playbook/references/product-message-design.md) |
| 優化ShineOn現有產品，或把方法轉用到相關／相似產品 | 先核exact SKU／variant及買家任務，再按本頁「產品優化」段選一個有證據支持的改善點；相關產品不因外觀相似便視為規格／需求相同 |
| POD競品、Trending／evergreen、社媒／廣告信號、需求判讀、成本／ROAS或測試假設 | [研究／經濟性](../../pod-university-playbook/references/research-economics.md)；課例只作教學線索，當前數據與成本另核 |
| 商品marketing research、Etsy SEO或keywords，且需要POD／送禮意圖／產品適配的判斷 | 沿用[既有keyword流程](keyword-coach-workflow.md)，在相應決策點補[產品／訊息](../../pod-university-playbook/references/product-message-design.md)及[研究判讀](../../pod-university-playbook/references/research-economics.md)，不另建選詞流程 |
| 已選POD商品的個人化輸入、圖片資訊、變體、履約或客服草稿 | [Listing／營運](../../pod-university-playbook/references/listing-operations.md) |
| 詢問POD University某課、出處、教學矛盾或引用 | [來源入口](../../pod-university-playbook/references/source-library.md)，按課名／時間碼定位 |

普通Etsy問答不必一律載入。本頁所列問題實際涉及POD課程方法時才讀；純CSV清理、簡單翻譯／格式、沒有POD關係的程式或其他領域工作不因此啟用。

## Marketing research、SEO與keywords的取用點

1. 查詞前：先用當前產品事實、買家／收禮者、場合及用途提出能改變決定的研究問題。重用有效Keyword Vault／既有原始觀察；知識包只補買家任務、訊息及產品適配，不把課例當搜索量。
2. 查詞與審核中：由現行工具及實際頁面取得需要的證據，保留exact query、來源、國家／scope、日期、窗口、指標定義及原值。eRank／EverBee的估算、平台觀察和第一方結果分開，來源核實不會把估算變成實際銷售。缺數據不自動當零。
3. 篩選與分配：接受、拒絕或hold均給產品／意圖／證據理由；準確但未量度的語句可保留假設，熱門但不符合實際產品的詞要排除。研究query可以較長；縮短或重組成tag後，不繼承長query的精確量度。標題、tags、分類／屬性及描述依既有keyword流程分工。
4. 內容與營銷：用同一定位協助自然文案、產品資訊及素材問題；品牌定位、故事、社群與渠道需要時沿用[既有品牌橋接](brand-marketing-routing.md)。不要求使用者自己選Skill，不重複啟動另一個研究庫或預算。
5. 檢討：用本店真實流量／訂單與定義正確的指標判讀，先保留基線與一個主要變量；教學原則可協助形成假設，不能代替因果證據或保證排名／成交。

上述是資料取用點，並非新的實作先後順序。完整新listing仍受原APOD／Digital的必要階段控制；不能因路由寫了SEO便提前做未到階段的keyword或copy。數碼交付只借適用的買家意圖與研究原則，不繼承實物材質、履約成本或物理產品規格。

## 產品優化與相似產品轉用

使用者提出「優化ShineOn產品／相關產品」時，可用以下視角診斷，但不要求每次逐項做完整審計。先從當前產品紀錄、已批准稿及買家證據找出最早未解問題，提出有理由的一個主要改善點。

- 買家與用途：付款者、收禮者、場合及實際使用是否清楚，產品是否真的能完成這個任務。
- 訊息與設計：原創表達、關係方向、可讀性、圖文層級、尺寸及載體是否一致。可參照課程方法，不照搬競品或按廣告量判定設計有效。
- 個人化與交付：買家能改甚麼、要交甚麼、文字／照片限制、是否需人工排版，以及preview／生成圖／實物是否分清。AI示例不證明現行自動化或保真。
- 商品方案與呈現：依真實規格檢查選項、圖片、包裝、價格／成本及履約；若需要Bundle，沿用既有品牌橋接及Bundle方法，不憑想像補SKU或優惠。
- 成效：用已知基線及一個主要變數驗證。畫面好看、自然語句、搜索量及實際成交分別驗證，沒有數據時只交假設與補證清單。

對相關產品，先比「相同收禮任務／情感訊息／用途」而非只看相同外形。記可重用的原創原則，並明列必須重新核對的材質、功能、印刷範圍、字量、個人化流程、成本、配送、素材權利及需求。期望來源可共用，不能把A產品的尺寸、熱門程度或供應能力搬到B。

例如個人化間線journal與LED plaque可以有相近送禮訊息，但前者的書寫用途與封面版面、後者的展示／亮燈可讀性及燈座規格需分別處理；同一PNG縮放不等於完成產品設計。Leather apron與fabric apron、pillowcase與含枕芯商品、canvas上的dog-tag圖樣與實體dog tag亦不能自動等同。

輸出優先沿用既有產品brief／檢查卡，簡明說明「已確認事實、主要問題、建議改動、可重用與需重驗部分、如何驗證及TBC」，不另建一套正式schema或取代既有製作流程。實際物料、製造品質或供應功能需要供應商／樣品證據，不能由教學文案直接優化成未提供的實體功能。

## 一份來源，一個產出owner

一次只讀解決目前問題的模組／來源段落，不預載整份課程圖。這個入口直接讀知識包的references；不再重新啟動另一個主流程，也不複製全部教學到本Etsy Skill。未來需要更新時，只更新經批准的知識包版本。

原有ShineOn供應商教練、Shine method、keyword流程、APOD mockup先行規則及Digital分支照其適用範圍執行。知識路由不改動它們的先後、數量、產物owner或human gate；例如讀到課程的keyword方法，不能越過現有實作階段的mockup gate開研究。

本店產品事實與當次owner決定優先。lined journal不寫成guided／雕刻；SKU、地區、平台及時間窗按來源分開。社媒互動／active ads不當利潤；Meta／Shopify教學不當Etsy設定；historical official checks不叫今日刷新。

## 缺口與授權

知識包不在本機時，用現有Etsy Skill及已可查的資料交有限草稿，說明POD課程補充不可用；不自動安裝、重建或假裝已讀。知識包有TBC／局部來源時，保留原證據層級，不能憑通用方法補出SKU功能、經文、權利或業績。

自動選方法只涉及閱讀及草稿。它不自動發佈、投放廣告、處理顧客資料、改正式決定、改Skills或新增費用；當次授權與既有批准底線照常適用。
