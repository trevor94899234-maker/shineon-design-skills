# Bounded private media handoff

Build a manifest for each exact asset: product ID and URL, verified title/variant, filename, source file identifier/version, bytes, SHA-256, duration, native/export dimensions, fps, current review/acceptance and intended action. Separate latest accepted files from superseded trials. Do not select a file solely because its filename says final.

Use an actually readable attachment or supported transfer. A cloud filesystem path is not a local download. Verify destination access, exact transferred bytes and same-SKU mapping before upload; missing files do not authorize broad filesystem scans. Assign one browser operator and one bounded task, and preserve existing media/order before changes.

Inspect the supported external-video upload route. An image/mockup file input is not an MP4 import route. “Generate Video” is not a substitute for uploading an existing film; do not click it to evade a missing import control or a denied action. Unknown route does not prove the platform cannot import video. A denial remains binding across machines and tools.

When an authorized supported route exists, upload the exact mapped file, save and reopen the same product, then check playback/duration and retained state. If uncertain whether an operation executed, inspect state before retrying. Keep old media recoverable under the task's scope; do not delete unrelated media or publish Etsy/social listings as a side effect.

Return separate counts and evidence for transfer, upload, save, reopen/playback and publication. An upload request or accepted file transfer is not a saved product. Record the exact missing control/permission/source if blocked, preserving the unchanged product state.

Case evidence: 19 October 2026 inspection of one APOD product found only Generate Video plus mockup upload, not a supported external MP4 control. No upload or save occurred. This is a dated UI finding, not a universal APOD limitation or a reason to use a different environment to bypass denial.
