# Asset transfer and recovery

## Resolve the source

- Resolve the approved asset and retain its stable identity, original filename, version if supplied, native dimensions, and SHA-256 when bytes are available.
- Distinguish original, preview, screenshot, resized export, name-removal trial, mockup, and printable PNG. Similar thumbnails are insufficient provenance.
- For Library files, follow the current Library skill and supported helper route for that result type. Retain authoritative returned identifiers and metadata. Do not invent paths or reconstruct private URLs.
- If metadata lookup, access checks, or a required helper fails, report the failure. Do not bypass it with hidden storage endpoints, a signed URL from another context, credential extraction, or browser session data.
- A file visibly accessible in an authorized browser may support a separate normal observed download route. Confirm it is the same file, download through the visible UI, and verify the result. Browser visibility does not prove a private API link is transferable.
- Keep login, upload authorization, file availability, and image fidelity separate. Login success does not prove upload success.

## Use the intended computer

- Use the explicitly selected and authorized computer/browser. Do not silently change environments.
- In a UI-only session, follow the actual computer-use tool restrictions. Do not add shell, filesystem, DOM, network, or clipboard workarounds those tools do not authorize.
- If supported transfer cannot complete, ask for the smallest missing action, such as selecting the already-approved original in Canva's upload dialog.

## Recover without fabricating progress

1. Re-read the visible state after any uncertain click, upload, download, or save.
   For an ordinary technical page error such as Aw, Snap!, promptly try one normal Reload after recording/protecting any unsaved work and checking whether the prior save/upload executed. Then inspect the actual recovered page and resume at the first unverified checkpoint. If the draft was lost, reconstruct only from verified evidence. If that plain Reload has no response, a second Reload is allowed only after verifying that no navigation or other action is active/pending and that unsaved work is protected. This is not a generic double-click instruction: never double Save, Import or Publish, and do not loop retries. Do not repeatedly reload or blindly repeat Save. This recovery rule never overrides a security warning, URL/protocol restriction, denied permission, whole-tool STOP or pending access decision; stop that affected operation and use only officially supported recovery when permitted.
2. Preserve the original and last clean design. Undo a known bad change; avoid repeating uncertain operations that could duplicate assets/designs.
3. Report the stopped checkpoint and what was actually verified.
4. Resume at the first unverified checkpoint once the missing asset, permission, login, or feature is available.

Never label an export complete because a thumbnail exists. Deliver a partial result only with explicit limitations.

## Export state is separate from design state

- A saved editable master can be verified while its export remains blocked. Report these statuses separately.
- Canva completion UI does not prove that the browser saved the file. A timed-out download event is an uncertain result; inspect the browser download entry and any actual file before retrying.
- Identify whether a visible security block belongs to the current attempt or an older download. Do not infer the current blocker from unrelated history.
- Do not bypass browser security warnings, force a blocked download, or extract an export through a private endpoint. Hand off the required user action when applicable.
- Until downloaded bytes are available, keep alpha, exact export dimensions, hash, and independent PNG fidelity checks unverified.
