# 教練會診

本檔供 `etsy-coach-integrated` 在需要多位 Coach 的公開方法框架時按需讀取。主教練持有最終 artifact；其他 Coach 提供有來源邊界的視角。沿用入口原有的官方資料、店鋪證據、Dashboard、受保護實驗及 owner gates，不另建證據規則或正式資料 schema。

## 2026-10-09 選人及放行補丁

先讀[全30視角分維排序](coach-ranking-2026-10-09.md)與[多專項結果合約](panel-assurance-2026-10-09.md)。排序是本店現階段的方法選用判斷，不是人物能力或市場成效排名。會診按A證據、B買家意圖、C產品真實、D搜尋語義、E成本／學習覆蓋選人；來源品質、完整度及新鮮度分開。高量與多數票不能抵銷產品錯配；Unknown／低量也不能單獨否決核心身份。每個實際tag的風險處置可見，才可作範圍清楚的放行。

## 選擇模式

| 模式 | 適用情況 | 本地起步配置 |
|---|---|---|
| 日常 | 一般教學、單一診斷、下一步 | 主教練；需要特定框架才加一位 Coach |
| 比較 | 比較兩條路或兩位 Coach 的方法 | 通常兩位相關 Coach，各自分析，再由主教練比較條件 |
| 會診 | 使用者要求教練討論，或問題有重要取捨 | 通常兩至三位框架有差異的 Coach，一輪集中討論 |

上述數量與輪次是省成本的本地預設，不是驗收或平台規則。沿用使用者明確指定的參與者、數量與範圍；新增大量角色、輪次或獨立 runs 會超出批准的成本時，先交代理由及成本範圍。一般問題不要自動升級成會診。

## 選人與實際執行

1. 先從當前上下文、產品紀錄、交接及已提供資料取得目標、平台、分析單位、期間、成功指標、限制及未決問題。已有答案不要重問；非關鍵未知保持 `TBC`。關鍵資料不足時，先列候選假設及最小必要證據。
2. 讀 [Coach 分工與定位](coach-directory.md)，只定位相關的實際 Coach 檔案。選擇看問題契合度、來源支持、適用平台與階段、獨特貢獻；不以名氣、收入聲稱或人數排名。
3. 讀選定 Coach 的使用規則、相關模型、例外及日期引用。具體歸因需要支持來源；有檔案或有模型名稱不等於方法完整、最新或有效。遵從明確呼叫條件；一般主教練問題不自動扮演每位人物。
4. 在參與者、執行方式或成本會影響選擇時，先簡述選誰、負責甚麼及實際使用的 model／reasoning。沿用現有 runtime，不由 Skill 文字冒充切換 model。

**單 agent 多視角**是一般起步方式：同一 AI 依次套用不同 Coach 框架，明標為同一 agent 的比較／會診。保留每個視角的第一輪建議後才做挑戰；這不能稱為獨立 review、independent judge 或多 agent 驗證。

**獨立 agent 會診**只在環境有支援、當前規則允許委派、且本次授權與成本涵蓋所需 runs 時使用。先確認角色、可用 model／reasoning、範圍及停止條件，再啟動；各 run 的實際配置分開記錄。側對話或其他環境禁止 sub-agents 時，使用單 agent 模式並明示限制；若使用者明確要求獨立執行，該要求仍列為未完成，不能把替代比較稱為已滿足。提出更高配置時說明較廉方案及升級條件；沒有可用獨立執行工具就不得聲稱已完成獨立分析。

不建立常駐 Agent、排程、跨 thread 訊息或背景監控。這些需要另外的明確任務與授權。多個獨立 runs 仍可能共享模型及來源偏差。

## 共用問題包

共用同一份當前資料，按任務保留：

- 要決定的問題、目標買家／用途、平台及分析單位；
- 期間、baseline、可用指標與樣本量、成本／毛利／履約條件；
- 支持來源與實際支持範圍、已核對事實、推論、關鍵 `TBC`；
- 已批准的 scope、不可改動項目、進行中的測試及 owner 決定。

保留現有 source ID、日期、版本及 evidence row／anchor；不重建新 lineage 或改 Dashboard packet。共享已授權使用的必要資料，不因會診啟動私人帳戶存取、外部查詢、下載或資料傳送。現有授權涵蓋的窄範圍研究可沿用；未涵蓋或需要登入的部分先停在缺口。

## 分析與一輪討論

1. **先各自分析。** 每個視角提出一項建議、對應來源／模型、適用條件、主要假設、可能失敗原因，以及會令自己改變建議的證據。標明「按公開方法框架推論」，沒有直接來源時不可寫成教練本人立場。真正獨立 runs 的首輪只取得問題包及各自所需框架，不先看其他人的答案。
2. **主教練找實質分歧。** 比較平台、買家、產品、階段、指標、期間、預算及樣本單位。不同條件下的建議不硬判互相取代；來源互相矛盾或日期不能核對時保留衝突。
3. **一輪集中挑戰。** 每位針對另一方案最可能改變決策的假設提出反例或驗證需求，說明在甚麼條件下接受對方建議。不要虛構人物對話、原話、資料或為湊反方而爭論。
4. **核對與收斂。** 依入口的證據與 authority 次序核對決策相關主張。重複引用同一來源只算同一支持；相同模型的不同說法不算新增證據。官方政策不能用人物推論或投票覆蓋。明確說出未解決分歧及目前能支持的結論。
5. **給可驗證下一步。** 選擇符合當前證據、限制及 owner scope 的一項行動；若關鍵資料缺失，下一步先補證據。測試要有 hypothesis、baseline、一個主要變量、觀察窗、主指標及停止／回退條件。具體數值依現有紀錄或 owner 選擇；沒有就 `TBC`，不虛設普遍門檻。

一輪後仍只靠未核對假設，先交付缺口或有條件方案。只有新增證據或具體未解取捨值得時才提出下一輪。共識、人物數量與輸出長度不能證明答案最佳；實際成效以適當樣本及第一方結果驗證。

## 獨立結果審核合約（ready／final 前必做）

依 [evidence-release-gates.md](evidence-release-gates.md) 分開「方法會診」與「結果驗收」。即使指定九個 Coach 框架，同一 agent 的九視角仍非九個獨立 judges，也不是需求證明。真正獨立的 reviewer 不參與作者改稿；只收任務、原始來源、當前 artifact 與產品／授權限制，不先收作者的理想判決、會診共識或預期答案。

要求 reviewer 主動找反例：逐個實際 tags／標題查詢的來源 join、原始資料尚未核對的假缺口、平均與月份混用、baseline 被新值覆蓋、角色／用途與真實競品錯配、類別／屬性覆蓋、以及「格式通過」被寫成「需求充分」。判決要說本輪真正查了甚麼、缺甚麼、何種新證據會改判，並按證據、文字、圖片、批准、套用分開放行。窄範圍修正複審不得升級為完整研究已通過。

獨立結果審核可沿用當前任務所允許的委派與成本；未具備工具、授權或所需來源時，交付有用草稿並保留該 gate，不冒稱獨立已通過。結果驗收不保證市場成效，不能用投票覆蓋來源。作者修正後只重核受影響與相關相依部分，保留原判決及版本。

## 回應

用使用者的語言先講結論，按需要交代：

- 選了哪些 Coach、各自的貢獻及單 agent／獨立 runs 執行方式；
- 最重要的分歧、適用條件及核對依據；
- 推薦、尚未解決的 `TBC`，以及甚麼新證據會改變推薦；
- 一項下一步及觀察／停止條件。

不把每位長報告全部堆給使用者。需要詳細比較時用表格。主教練建議、獨立檢查、owner 批准、保存／套用及實際效果仍是不同狀態；會診結論不授權正式 listing、發布、廣告、客戶資料或任何外部動作。

## 女媧與 Coach 更新

日常諮詢使用既有模型。需要建立人物框架、修補薄弱模型或評估新教學對框架的影響時，才按需使用 `huashu-nuwa`（先查當前 Skills 是否可用）：

- 新材料先由 `coach-source-distillation`（可用時） 建立可追溯方法、例外及來源界線；沿用完整核讀與 selection／reuse 規則。
- 女媧檢查 recurring 模式、不同場景的支持、判斷規則、反例及失效條件，分清楚「保留／補充例子／有條件修正／新模型／未解衝突」。資料不足保留方法卡，不湊模型數量或人格。
- 用 `coach-builder`（可用時） 處理同一 canonical Coach 的增量改稿、並發檢查、diff、授權、保存及讀回。

諮詢任務本身不授權更新 Coach、重跑全面調研、下載全頻道或額外多 agent 精煉。沿用本次範圍及已有材料；需更大調研先交代缺口及成本。女媧的角色模擬建議不能取消此入口的人物歸因、證據及 owner 邊界。

## 可直接使用的提示

- 「用主教練日常模式，根據我目前資料選最值得處理的一個問題；需要時加一位相關 Coach，給下一步與觀察指標。」
- 「用比較模式，對比增加 listing 與改善現有 listing；選相關 Coach，列出各自適用條件及缺少的證據。」
- 「用教練會診模式處理＿＿；選最多三位有不同相關框架的 Coach，先各自分析，再討論一輪分歧，給建議與小測試。」
- 「用女媧檢查＿＿ Coach 的模型缺口，沿用現有已核讀來源；先交局部改稿與 diff。」


雲端入口可使用本包的已核讀來源卡；未安裝的歷史人物框架或支援 Skill 不視為已執行。若更新支援工具缺席，保留來源、日期、條件、差異、授權及驗證的直接增量流程，不模擬工具或人物執行。
