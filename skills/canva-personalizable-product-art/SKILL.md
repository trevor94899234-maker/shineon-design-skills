## Establish the task

1. Identify the approved original artwork, product, printable surface, supplier specification, requested custom text, and final deliverables.
2. Record the source file's native pixel dimensions separately from the intended Canva canvas and export dimensions. Do not infer native resolution from a preview, filename, resized download, or design settings.
3. Confirm the requested scope of editability: normally the custom name is editable text and the remaining art is one raster layer. Do not imply that every illustration or baked-in text line becomes editable.
4. Preserve the original file and original Canva design. Create a private working design or authorized duplicate, and keep failed trials distinguishable from approved masters.
5. Check that the user authorized upload to Canva. Never make an image public to satisfy an import tool. Use supported local-file upload or the current Library transfer route; see [transfer-and-recovery.md](references/transfer-and-recovery.md).
6. Honor an explicit computer-use request. Observe and operate the actual Canva UI in the selected environment. Do not silently substitute generated designs, a connector edit, or a different computer. If a route is unavailable, report the precise blocker and ask only for the missing choice or action.

Before continuing, complete the source and specification fields in [run-record-template.md](references/run-record-template.md). ## APOD editable-artwork route

For authorized Canva-to-APOD editable or personalizable product artwork, prefer the official **Add Layers From Canva → Import Layers** route when available, rather than flattening the design to PNG first. Read [layer import and verification](references/apod-canva-layer-import.md). This preference does not establish editable text, correct fonts, transparency or successful saving: verify each. It applies to actual product artwork, not listing thumbnails. Continue using built-in image generation for complete UGC-style thumbnails and their text; do not compose those thumbnails in Canva.

## Native APOD custom-text sizing

For every authorized personalizable product build or revision, read [two-mode sizing and QA](references/apod-custom-text-sizing.md) before setting a name, date or other supported text field. Choose from actually observed controls: fixed usable box with dynamic font fitting, or fixed font size with deliberately reserved expansion space. Do not default to an unnecessarily narrow box or shrink every long name without reviewing available print area. Fixed-size mode is not automatic safe-area protection. Verify short, normal and long inputs, restore the intended default, save and reopen; native canvas QA and actual supplier mockup QA are separate. This checkpoint does not authorize batch-editing all existing products, redrawing fixed artwork, publishing or changing prices.

Count files from verified file records, distinguishing folders/shortcuts and unresolved MIME types; reconcile category subtotals before reporting a batch count.

For each font record four different facts: delivered font file; actual selected native text family/style; application availability/origin (library or uploaded, when exposed); applicable commercial/POD and embedding/hosting rights. A DEMO/trial/personal-use filename is a targeted rights flag, not proof that the design actually uses it or that every project is blocked. Inspect the actual text selections using a supported authorized route. If an API does not expose font/colour/origin, record that API limitation and retain independently verified evidence. Inspect the actual native text controls/picker through a permitted route rather than infer the font from glyph appearance; do not turn one tool's missing fields into a universal Canva limitation. Verify rights only for assets actually needed, preserving unresolved dependencies; never bulk-upload all delivered fonts. No licence file found in inspected folders is not proof no licence exists. Request the specific licence evidence or propose a disclosed suitable substitution when needed, without silently changing an approved font.

## Core creative gate: message, title and image work together

At planning/intake, identify one buyer, recipient/relationship and occasion, then state the feeling the design aims to express in one sentence. A title/headline, body message and visual should form one original, meaningful story—not a stack of decoration. Carry the brief through Canva composition and final review, using `etsy-pod-image-prompts` for the same creative gate rather than starting another design process.

Preserve approved wording/art. Set an intentional hierarchy among the editable name, message and motif; ensure ornament or a large title does not unintentionally bury the emotional message. If the approved source fails this goal, explain the problem and propose a bounded revision for approval instead of silently redesigning during transfer. Do not force extra text into a no-overlay brief.

Review the combined title, body and image against the chosen recipient's moment. Compare a new variant with the actual previous version for meaning, clarity and hierarchy before cloning a larger series. Keep technical/export QA, creative recommendation and owner approval of the exact version separate; a transparent PNG or a reviewer's preference does not mean the design is emotionally effective or approved. A decorative intermediate asset is still not a finished gift design.

Use respectful faith language and clearly distinguish original blessings from verified Bible quotations. Check source/translation/usage rights before attribution; invent no verses, guaranteed recipient feelings, spiritual outcomes or sales claims. Keep the record brief: intended feeling, text/visual support and approval status. Do not hard-code any current sample wording or reviewer-preferred variant as permanently approved.

For new personalizable gift art, treat the recipient/name as the protagonist. The title, body and illustration support them; the name must not feel tacked on beneath overpowering decoration. Reserve a compact, integrated name position with intentional spacing, not a large empty placeholder void. Apply this to original personalized product artwork, not every listing overlay or an unapproved redesign of an existing master.

Prefer the complete fixed title/body/art generated together, with the custom name omitted entirely, then add only the native editable name in Canva using a coordinated font verified in its picker. Do not rebuild all fixed text/illustration by default or generate a name merely to erase it later; repair authorized wording only in Canva; visual-art corrections use the built-in image-generation tool, respecting approved-art scope. Read back every fixed line. Before expanding the series, inspect actual rendered proofs with a short name, a long name and the restored intended final name at print scale. Assess prominence, compactness, balance and emotional meaning with the name present; the name-free art is insufficient. Reuse these existing name tests rather than creating another QA loop. Latest explicit authorization for an identified version or expansion counts; do not demand duplicate approval. Keep print-order and publication permissions separate.

## Mandatory artwork intake and print-scale gates

Default to one complete background-free transparent PNG per design/SKU/print area, alongside its editable Canva master. Use a different background/format only for a recorded, verified supplier/process exception.

- Require one independent, complete composition for each product design from generation onward, with a reserved name area. Verify the intended SKU/surface, physical size, aspect ratio, canvas, resolution, bleed and safe-area requirements before production-oriented generation; unknowns mean provisional work. Three designs must start as three independent artwork files, never a triptych/collage to crop apart or patch. Review boards may be assembled afterward only for review, never used as print sources.
- For a shared theme across multiple products, require a separate complete composition/master/export for every confirmed SKU, variant and print area. Journal plus acrylic plaque means two independently fitted layouts, likewise bags or shirts; never stretch/crop one universal bitmap. Confirm width/height and units/pixels, ratio, bleed, safe area, process and background for each. Historical 1410 × 2220 journal or 3540 × 3186 plaque examples do not verify a current SKU.
- Label each file with product/variant/print area, actual dimensions and ratio, artifact role and verified/provisional status, using filenames where practical plus one compact mapping manifest. Bind each preview to the correct independent master/export; preserve native, canvas and export sizes separately. Missing specification evidence blocks direct production use. Refer multi-product cost, packaging and separate-shipment decisions to the existing `brand-marketing-growth` Bundle checks, rather than treating matching designs as an approved bundle.
- Distinguish intermediate illustration assets, complete compositions, editable Canva masters, review/mockup images and verified final production files. A transparent ornament alone is not a finished product. Measure native generation dimensions; request the intended aspect ratio but do not claim the tool produced exact supplier pixels without checking. Lay out the whole composition plus native editable name on the actual verified Canva canvas, then export one complete file per design. No segment extraction, stretching, patching missing artwork or upscaling-as-quality shortcut.
- For newly generated standalone print art, require the upstream generation to use native transparency, with the actual transparent-background option enabled when available. Keep brown/cream substrate color, leather/paper texture, product silhouette and scene lighting in a separate preview, not baked into the production artwork. Prompt text, an editor checkerboard or later background removal is not proof that the source was generated with alpha. Read `etsy-pod-image-prompts` for the original-art prompt gate when needed; do not regenerate the current approved asset merely to re-run this rule.
- Keep each custom name as a separately selectable native Canva text element. Generate new static art name-free. Preserve approved fixed artwork and explicitly state which other text remains raster; do not imply every text line is editable. Existing baked-in names follow the limited, fidelity-preserving repair path below, not an automatic whole-art redesign.
- Use simple, readable raster compositions: clear motifs, strong linework and enough stroke width/gaps at the actual print dimensions. Avoid microdetail, hairlines, microtext and crowded ornament. Check current supplier/SKU/process limits; never invent one minimum pixel width for every product. Enlargement or DPI metadata does not repair insufficient source detail or dense composition.
- Check approved art before production handoff. If detail is too fine, flag the affected region and seek approval for simplification; do not silently change approved art during Canva transfer. Check small and long names at the real print size as well as in the editable canvas.
- Verify the exported PNG's actual required alpha and visible background on light/dark surfaces, alongside dimensions and print-scale readability. Keep a separately named preview, editable master and production file. Transparency is not a guarantee of print quality.
- Treat supplier-confirmed full-bleed, engraving/cut or other non-transparent requirements as documented exceptions. Record the real template/process and required format/background, then verify those requirements instead of forcing transparent PNG. Do not promise a universal process based on file extension.

## Execute one checkpoint at a time

Use a current screenshot before each new control sequence. Read the visible label, perform the small action, then capture the resulting state. Do not guess coordinates, menu labels, hidden layers, or the success of an asynchronous operation. Complete each checkpoint without relying on unstated assumptions.

### A. Confirm the canvas

- Verify the signed-in Canva account/workspace is the intended destination without exposing account details.
- Create or duplicate the authorized design; record its visible title and actual edit URL.
- Set custom width, height, and units from the supplied product specification. Read back both values in the UI and verify orientation.
- For the supplied ShineOn Graphic Journal FRONT example, use 1410 × 2220 px only when the same user-provided specification applies. This is a front design, not a wrap or back/spine template. Do not invent extra bleed, trim dimensions, or a universal print-safe margin.
- Preserve proportions and the complete composition. If the original ratio differs, use only an approved non-destructive fit/padding or correct/regenerate the composition within authorization; do not crop away sections, stretch, extract collage panels or patch missing art to fill the page. Record actual source pixels separately from canvas/export dimensions.

### B. Place approved art

- Upload the exact approved file and compare the inserted result against it before editing.
- Keep the static artwork on a separate layer from the custom name. Lock it when practical after its position is verified.
- Record actual placement/scale and a full-page screenshot. Do not crop letters, illustration tips, or ornamental edges.
- If the source contains the name as pixels, continue to C. Otherwise confirm the name area is truly clear and continue to D.

### C. Remove only the baked-in name

- Prefer a verified name-free original or layered source. Never substitute a generated approximation merely because it resembles the approved design.
- Work on a duplicate. The observed seed route was: select uploaded image → Eraser → Pixel Eraser. Use it only when those controls are actually visible; do not substitute Magic Eraser by assumption. Verify the effect instead of assuming that a tool name guarantees success.
- Keep the mask or erasure tightly limited to the name. Do not erase nearby art, fixed text, borders, strokes, or texture.
- Do not cover the name with an opaque rectangle on artwork intended to have a transparent background. A patch matching the editor's page color will appear in the export.
- Compare the changed region and surroundings at enlarged view. Check ghost letters, haze, rectangular edges, halos, softened nearby lettering, missing art, and shifted/cropped religious symbols or ornaments.
- Inspect against light and dark temporary backgrounds. Remove diagnostic backgrounds before export.
- If approved content changes or remnants remain, undo and stop this branch. Report the unresolved defect; use a clean original or a permitted built-in image-generation correction. Do not use Canva/vector/code reconstruction to repair visual art. Do not call a defective file name-free, transparent, or faithful.

### D. Add independent editable text

- Add an actual Canva text element for each independently personalized name or name pair. Select the text separately from the art and read its content back.
- Use exact authorized spelling, punctuation, case, and accents. Preserve fixed wording.
- Search Canva's actual font picker and select a visibly available family/style. Record both. Libre Baskerville Bold or Italic may be proposed stylistic substitutes; do not call either an identified AI-image font or claim availability without observing it.
- Select the complete text before applying its color/style. Read the intended color value back, then verify the rendered letters themselves; a correct toolbar value does not prove the exported glyph color. Match approved hierarchy, color, spacing, alignment, and position closely. If the raster source's exact font is unknown, disclose the chosen matching style.
- Test a short and a long representative name in the actual text element. Reduce font size or adjust the approved text box when needed; do not treat one sample’s size as a universal setting. Check wrapping, clipping, overlap, edge clearance, and balance. Use a duplicate page or undo after each test; restore and re-read the intended final name.
- Verify static art did not move during name edits. Record change/undo results and final state. A PNG containing a name is not evidence of editability.

### E. Audit the complete design

- Read every line of fixed and custom text against the approved original, not only the headline.
- Compare layout, illustrations, colors, proportions, borders, and fine details. Use [product-fidelity-and-print.md](references/product-fidelity-and-print.md).
- Confirm only intended personalization changed. Do not approve a redesign as a successful transfer. If a late audit finds nearby art pixels removed, disclose and flag the affected region; keep exact-art-fidelity approval pending until the user accepts the change or the art is restored. A visually clean name area does not prove pixel-identical preservation.
- Confirm the independent editable element persists after saving and reselecting/reopening the design.
- Keep a full-design proof and close-up of the cleaned/name region. Record the current design link.

### F. Export and verify

- Select the intended page and supplier-required format in the actual export UI. For the normal standalone transparent-PNG deliverable, enable transparent background and verify its availability and authorization; if unavailable, mark this route blocked rather than silently exporting opaque art. For a documented supplier exception, use its verified background/format. Verify output dimensions, including any size multiplier.
- Pause if a paid feature, upgrade, new agreement, or permission blocks export. Do not purchase or alter the account to complete a download.
- Observe download completion. Verify the actual downloaded file, not just a toast or filename. If an event times out, inspect the visible download state before retrying. Never bypass a browser security warning; hand off an unblock action when required.
- When file access is available and authorized, run the read-only inspector on a PNG deliverable. This command uses the seed journal dimensions; substitute the current product’s verified width and height. Use `--require-transparent` only when transparency is the verified requirement. A documented non-transparent PNG exception omits that flag and checks the required background separately; another required format needs a format-appropriate verifier, not a fabricated PNG pass:

  `python3 scripts/inspect_png.py EXPORT.png --expected-width 1410 --expected-height 2220 --require-transparent --source ORIGINAL.png`

- The inspector requires Pillow. Run only in an environment where file access and script execution are available and authorized. A UI-only session does not authorize another access route. If only visual checks are possible, report dimensions/transparency/hash as unverified where applicable.
- Inspect the exported PNG on light and dark backgrounds. Verify the intended text color in actual exported glyphs; when bytes are accessible, add repeated `--probe X,Y` options for observed fully opaque glyph-interior pixels. Avoid antialiased edges, transparent pixels, and adjacent artwork; pixel samples alone do not identify the correct region. Alpha presence alone does not prove a clean transparent background; a checkerboard painted into pixels is not transparency.
- Distinguish source detail from output size. A 1000 × 1573 source enlarged to 1410 × 2220 retains its original raster detail. Do not label resampling true higher-resolution art or guarantee print quality.
- Compare delivery bytes separately from local export bytes. If a chat image has different dimensions, do not assume Canva exported incorrectly or silently upscale the received copy. Use a supported original-file or archive delivery route when needed, then verify dimensions and SHA-256 again; `--expected-sha256 MEASURED_HASH` checks identity against a measured original export. Preserve the original and editable master. Deliver the native PNG attachment and verified Canva edit link, with relevant font-substitution, unresolved-check, and enlargement notes. Do not claim production approval until necessary supplier/physical proofs are checked.

Complete one [run record](references/run-record-template.md) per design. Separate PASS, FAIL, BLOCKED, and NOT CHECKED; never convert a blocker into a pass. Include artifact links, export dimensions, alpha result, SHA-256 when measured, actual editable-text tests, and supplier/physical proof still pending.
