# Completion, proof and delivery

Report the requested endpoint separately from technical fidelity, owner acceptance, actual saved application and publication readiness. A record can be complete for a specifically authorized private-draft scope while containing disclosed technical HOLDs; it cannot silently become ordinary PASS or a public release.

## Reconcile the required outputs

For each active required role verify: current design/brief; actual native path/hash/decoded dimensions; distinct buyer coverage; technical QA and required independent evaluators; exact-file or explicit scoped-policy use eligibility; APOD asset identity; selection/order/primary; saved/reopened evidence after the relevant last mutation. Keep requested count, attempted calls, returned files, size-compliant files, technically passed files, use-authorized files, uploaded, selected, saved, verified and published counts separate.

For every applicable listing field compare expected versus actual saved value, or give a truthful disposition/reason. Include nested personalization configuration; a main-form title match does not prove instructions saved. Compare full description including warning, tag set/count/limits and actual order separately, original artwork/variant links and protected controls. Complete the final readback after the last gallery/video save that might affect those fields.

Required missing evidence, pending human gates and unexplained drift keep that dependent work incomplete. `NOT_EXPOSED` identifies a real platform capability limit; it is not a disguised PASS for a required editable field. Owner exclusions must cite actual decisions. Don't silently narrow a goal to make the record pass.

## Use authority and technical evidence remain separate

- `TECHNICAL_PASS`: every relevant technical check passed on these bytes.
- `USE_AUTHORIZED_EXACT_EXCEPTION`: exact bytes accepted despite named findings, for stated use only.
- `USE_AUTHORIZED_SCOPED_POLICY`: exact bytes checked after generation and bound to a current explicit policy; retain `human_viewed_exact_file=false/unknown` when appropriate.
- `HOLD`: no currently eligible use path; disclose the dependency and next action.

The latter two do not certify original-logo pixels, geometry, physical print, arbitrary-name fit, truthful claims that lack evidence, or permission to publish. Scope-specific draft warnings and disclosures remain unless explicitly resolved and removal authorized. A blanket “all done” is inappropriate if the result is only local preparation or a subset of fields.

## Suggested final states

Use existing coordinator state names where present: `PREPARED_LOCAL`, `PARTIAL_APOD_APPLIED`, `COMPLETE_AUTHORIZED_PRIVATE_SCOPE`, `APOD_READY_FOR_OWNER_REVIEW`, `ETSY_PUBLISHED`. Explain the exact active endpoint rather than inferring meaning from a label. Claim `ETSY_PUBLISHED` only with authorized actual publication and verification. Do not click Push to finish a private task.

Deliver the exact eligible native files, role/source/authority manifest, full field matrix, application receipts and a clearly labeled derived contact sheet. A ZIP must contain the expected entries with matching SHA/CRC; a contact sheet proves neither native dimensions nor exact file identity. Include rejected candidates only when requested, clearly separate from eligible deliverables and retaining their provenance.

The generic coordinator's `audit_delivery.py` can audit its documented record schema. Use it only with a truthful schema mapping; it checks records/bytes, not live UI, visual fidelity or legal authority. Preserve original `REVISE` verdicts alongside any normalized `HOLD` required by that schema. A scoped-policy receipt must explicitly bind every audited hash and the human policy; don't fill an “exact exception” slot as if the owner viewed future files. If a schema cannot represent the actual authority, extend the report honestly rather than fabricating a compatible fact.

## Final response pattern

State what is complete and link the product/result. Report N/N **saved and verified**, primary/order, applicable text fields and video only when in scope. Say if acceptance uses disclosed exceptions. Name important unresolved release items and owner exclusions without asking them again. Link the manifest/ZIP and evidence. Distinguish local automated checks, recorded browser evidence, current live verification and human review; none substitutes for the others.
